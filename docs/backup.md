# 备份与恢复契约

项目状态和下一动作仅维护在 `../PLAN.md`。

- 书架 → 更多 → 备份与恢复。用户已选择V1整库替换；导出通过系统文件选择器保存，恢复先选择文件、完整预检，再显示日期、书籍/图片/生词/书签/译文数量以及明确替换提示。只有点“替换并恢复”才写数据库；取消或校验失败保持原数据。空备份也必须确认，会清空这七张业务表。
- 保存书籍的已解析正文（包括章节、补充脚注、链接、锚点、图注/表格）和图片资源、书名/ID/时间、整数与精确阅读位置、单书和全局设置、生词全部快照与语言/来源/许可、书签、成功译文缓存及最近查词历史。已删除书籍的生词快照继续保留，不按书名重新绑定。保留原始JSON字符串和源偏移，不重解析EPUB、不重写位置/页码。
- 可选作者列表和封面资源键随原书籍JSON保留，封面图片复用book_assets；预检同时检查封面引用的资源存在，即使正文未使用该图片也不能遗漏。旧JSON没有这两个字段仍兼容，无备份版本/schema变更；封面识别与显示边界见 [阅读契约](epub-links.md#书架作者与封面)。
- 不包含原始EPUB/TXT文件（现有导入本来只保存解析结果）、词典数据库、系统翻译模型、临时搜索栈或应用二进制。词典/模型在新设备另行准备；同设备恢复不删除它们。译文保留原engine/语言对，因此另一平台不会把不匹配引擎的缓存当作本机结果。
- 文件扩展名`.readingbackup`。v1为20字节头：`READING\n`八字节，随后三个大端uint32：格式版本1、payload字节长度、payload CRC32。payload是UTF-8 JSON：format=`Reading backup`、schema=7、createdAt毫秒时间、tables。tables为七个固定表名，每行按`backupColumns`固定列序保存；BLOB使用base64。无文件内SQL、无SQLite文件替换、无压缩、无路径解包。CRC32检测意外损坏，不是签名、认证或加密；界面明确备份未加密。
- schema7所有七表必须存在（含lookup_history），空表用空数组；缺表、未知文件版本/schema、长度/CRC不匹配、错误类型、坏正文JSON、重复主键/复合唯一键、孤立图片或书签、图片资源缺失均拒绝。资源路径须是规范包内路径，不接受绝对路径、点段、反斜线、冒号或空段。路径只作为数据库键，不写任意文件或执行外链。已有BookContent旧JSON的缺省字段继续由当前解析器兼容；历史位置/样式字符串保留，阅读器原有坏锚点拒绝/样式回退规则保持。
- 明确资源上限：文件64MiB；各行字符串UTF-8（图片计base64文本）合计32MiB；500本书、10,000图片、七表共50,000行、1,000译文、200条查词历史，单图解码字节20MiB。JSON深度最多32、容器25万、字段分隔符100万；正文等嵌套JSON独立预检。文件流累计字节超限立即停止；数据库导出先估算行数/字节再读取，每步仍检查最终编码限额。超限拒绝整次操作，不偷偷截断导出，也不部分恢复。
- 继续兼容v1/schema6旧文件：严格检查原六表，预检结果补充空lookup_history；整库恢复因此会清空现有查词历史，确认页明确列出历史数量及替换范围。新文件仍为v1封装，payload的schema7让旧版应用明确拒绝，需新版恢复。历史按语言/精确原词去重，非空、长度/控制字符限制及200条上限沿用history.md，未知schema仍拒绝。
- `BackupStore.export`在只读事务里取一致快照，保留原行顺序（含缓存FIFO）；编码/校验在compute隔离线程完成。`ReadingBackup.decode`返回不可变预检快照，确认和恢复使用同一内容，不重新打开可能已变化的文件。
- `BackupStore.restore`对固定七表做参数化插入，在同一个drift事务中删除旧内容并恢复新内容。磁盘/约束/插入失败由事务整体回滚，不存在先清空再单独导入的窗口；不改变当前schema7。此保证依赖SQLite正常事务/文件系统行为，不声称能恢复设备物理损坏。
- 恢复仅从书架进入，执行期间禁用按钮与返回，防止旧阅读器/旧列表继续操作。`LookupHistory.replace`先失效旧查词并排空历史写入，再调用`CachedTranslator.replaceCache`提升请求代次并串行等待旧缓存写入，过期原生结果不能在成功或失败恢复后污染缓存；恢复成功刷新书架和全局设置provider。不会重建正在使用的数据库连接或使词典实例失效。
- 启动续读开关按普通settings记录备份；旧备份缺项默认关闭。恢复后刷新设置，不立即自动进入阅读；具体兼容规则见 [启动契约](startup.md)。
- 阅读方向偏好也按settings备份，恢复后刷新；旧备份缺项跟随系统，在书架不应用方向限制，见 [阅读方向](orientation.md)。
- 本模块不做合并、自动备份、云同步、密码保护、多语言或超大书库流式格式。当前有限内存方案仍需低内存设备与接近上限书库体验；系统文件保存/选择由原生插件负责，组件测试不代替真机验收。工程测试在独立临时库中做破坏性恢复，不向用户设备注入/替换测试数据。
